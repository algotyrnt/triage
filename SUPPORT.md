# Support Guidelines

Need help with **Triage**? This document will help you find the right place to get answers quickly.

---

## 1. Documentation & Guides

Before opening an issue, check our official documentation for answers to common questions, deployment architectures, and integration guides:

- **Official Documentation**: [triage.algotyrnt.com](https://triage.algotyrnt.com)
- **5-Minute Quickstart**: [triage.algotyrnt.com/docs/quickstart](https://triage.algotyrnt.com/docs/quickstart)
- **Go SDK Integration**: [triage.algotyrnt.com/docs/sdk](https://triage.algotyrnt.com/docs/sdk)
- **Self-Hosting Guide**: [triage.algotyrnt.com/docs/self-hosting](https://triage.algotyrnt.com/docs/self-hosting)
- **Troubleshooting & FAQ**: [triage.algotyrnt.com/docs/troubleshooting](https://triage.algotyrnt.com/docs/troubleshooting)

---

## 2. Community Q&A & Discussions

For general questions, architecture advice, best practices, and sharing ideas:

- Visit **[GitHub Discussions](https://github.com/algotyrnt/triage/discussions)**:
  - **Q&A**: Ask how to configure Triage or integrate with your specific Go framework.
  - **Ideas**: Share suggestions for new features, LLM providers, or tooling.
  - **Show and Tell**: Share how you are running Triage in your infrastructure.

---

## 3. Reporting Bugs

If you have encountered a bug or unexpected behavior:
1. Search [existing open and closed issues](https://github.com/algotyrnt/triage/issues) to see if it has already been reported.
2. If not, submit a new bug report using our [Bug Report Form](https://github.com/algotyrnt/triage/issues/new?template=bug_report.yml). Provide a minimal reproducible example, stack traces, and environment details.

---

## 4. Feature Proposals

Have a concrete proposal for Triage?
- Submit a proposal using our [Feature Request Form](https://github.com/algotyrnt/triage/issues/new?template=feature_request.yml).
- Or start a conversation in [GitHub Discussions](https://github.com/algotyrnt/triage/discussions/categories/ideas) to gather feedback from the community before drafting an implementation.

---

## 5. Security Vulnerabilities

Please **do not** open public issues for security vulnerabilities. Review our [Security Policy](SECURITY.md) to report security issues privately.
